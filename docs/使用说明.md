# Codex 手机通知：EXE 使用说明

版本：1.2.1 · 更新：2026-11-02

当前提供两个独立开关：“输入框建议提醒”和“需要回答时提醒”，双击蓝色托盘图标即可设置，自动保存。配置缺少对应选项时默认关闭，启用前还需审核所用 hooks。操作、原理和适用范围见[交互提醒](交互提醒.md)。建议开关关闭时继续过滤自动建议，正式回复不受影响。

设置窗口默认内容区为 920 × 860（100% 缩放），可完整显示各项设置。Windows 高缩放下会相应放大；屏幕空间不足时限制窗口尺寸并允许滚动。关闭窗口后继续在托盘运行。

本工具在 Codex 主会话每轮结束后向 Pushover 排队发送一条通知，显示项目名称、该轮用户输入和本轮回复。通知内容会经过 Pushover 服务，不需要手机与电脑建立 Codex Remote 连接。

## 日常使用

双击桌面的“Codex 手机通知”快捷方式，程序会进入托盘；双击托盘图标打开设置。直接双击 `CodexPushover.exe` 也能打开设置。找不到图标时，先展开任务栏的隐藏图标。

| 操作 | 在哪里做 | 实际效果 |
| --- | --- | --- |
| 查看状态 | 托盘 → 状态与设置 | 查看凭据、接口接受数、待发数和后台状态 |
| 修改凭据 | 设置 → Pushover 凭据 → 保存更改 | 输入框默认隐藏内容；留空保留已有值 |
| 调整通知长度 | 设置 → 用户输入显示上限 → 保存更改 | 默认 200 字符，可设 8–400；其余空间留给回复 |
| 暂停或恢复通知 | 托盘 → 暂停 / 恢复手机通知 | 暂停时停止新回合入队；旧队列保留 |
| 输入框建议提醒 | 设置 → 输入框建议提醒 | 推送可按 Tab 采纳的下一步输入建议；开关自动保存 |
| 需要回答时提醒 | 设置 → 需要回答时提醒 | 本机提问工具请求回答或选择时推送；需信任 PreToolUse |
| 修正凭据或额度后继续 | 托盘 → 解除发送错误暂停 | 重新开放因 4xx 错误暂停的记录 |
| 设置登录启动 | 设置 → 登录后自动运行 | 创建或删除当前用户启动文件夹中的快捷方式 |
| 测试发送 | 托盘 → 发送测试通知 | 加入一条独立测试通知，不代表手机已收到 |
| 退出 | 托盘 → 退出程序（保留待发） | 等待当前发送结束后退出两个后台进程 |

关闭设置窗口只会把它隐藏，托盘继续运行。退出程序后，hooks 不会立即将它重新拉起；下次手动打开或登录自启动会恢复运行。如果你关闭了设置中的“手机通知”开关，重启电脑后仍会保持暂停。

每轮正式回复一条；开启交互提醒后，可另收到提问或输入建议。每条正文最多 1024 个 Unicode 字符，超长时截断并标注。关闭某一类交互提醒会取消该类尚未发出的记录，重新打开不会补发这些记录；已开始发送的请求无法撤回。调整显示长度不会改写已经固定的待发正文。

界面采用蓝色 `#2563EB`、浅蓝灰背景和微软雅黑 UI，统一按钮、开关与托盘菜单。窗口图像嵌入 1254 × 1254 高清资源；托盘和程序图标提供多尺寸帧，按显示大小选择。较小窗口允许正文滚动，底部操作按钮保留在窗口中。

状态查询和设置写入放在后台执行，拖动窗口时延后更新文字，松开后再刷新；通知发送与心跳检查继续运行。本机 175% 缩放下的截字和数值输入框重复缩放问题已修复。

## 文件、进程和启动项

本机可执行文件：

```text
%LOCALAPPDATA%\CodexPushover\CodexPushover.exe
```

数据也保存在这个私有目录中。凭据文件是 `credentials.json`，其中包含 `PUSHOVER_APP_TOKEN` 和 `PUSHOVER_USER_KEY`。不要将真实凭据发到聊天、放进项目仓库，或随 EXE 分发。

程序只有一个 EXE 文件，但正常运行时有两个常驻 `CodexPushover.exe` 进程：`--tray` 或 `--settings` 负责托盘和发送，`--guard` 负责检查托盘进程。hook 调用会出现短暂的第三个进程，处理完本地事件便退出。

在任务管理器“详细信息”页右键列标题，勾选“命令行”。核对完整 EXE 路径，以及 `--tray`／`--settings`（托盘）或 `--guard`（守护）参数；PID 每次启动都会变化。

按 Win + R，输入下面的命令，可以管理本工具的登录启动快捷方式：

```text
shell:startup
```

快捷方式名称为 `Codex 手机通知.lnk`，目标是私有目录中的 EXE，参数是 `--tray`。这一版使用启动文件夹，不注册计划任务，也不靠旧的注册表 Run 项、Node、PowerShell 或 VBS 启动通知。

## 三个 hooks 分别做什么

`UserPromptSubmit` 保存该轮用户输入并识别自动建议回合；`Stop` 将正式回复或建议入队；`PreToolUse` 只匹配提问工具，保存问题和选项。三个不同事件分别注册，共用一个命令入口：

```text
cmd.exe /d /c call "%LOCALAPPDATA%\CodexPushover\CodexPushover.exe" hook
```

三个事件都从标准输入读取官方事件 JSON，并快速返回 `{}`。hook 只写本机记录和请求唤醒后台，网络发送由常驻进程完成。第三项只匹配 `request_user_input`、`request_user_input_async` 及其 `functions.` 前缀，不会为每个普通命令启动通知程序，也不会自动回答或批准操作。

在 Codex“设置 → Hooks”刷新，查看并信任 `UserPromptSubmit`、`Stop`、`PreToolUse`；也可使用“Review hooks”。添加或修改定义后按界面提示审核，不能复制其他电脑的信任记录。只有前两项时，仍可推送正式回复和输入框建议；提问时提醒需要第三项。

## 自动恢复的范围

托盘每 5 秒检查守护进程，守护每 10 秒检查托盘。心跳或发送进度超过 120 秒没有更新时，另一端会核对 EXE 路径、PID 和进程启动时间，再尝试重启。常驻监督的单端恢复每 5 分钟最多启动 6 次；hook 唤醒另有 30 秒节流，避免重复启动。

两个进程都退出或被拦截时，需要下一次有效 hook、登录启动或手动打开 EXE 恢复。主动退出、主动暂停和迁移期间会限制自动唤醒。本工具是用户程序，关机、注销和休眠期间不能发送。

网络请求最长等待约 10 秒。网络错误与 5xx 先按 5 秒、30 秒重试，之后每 15 分钟探测一次，待发记录一直保留。请求进行中进程退出后，也会保留 15 分钟冷却，减少重复发送的风险；网络超时无法保证严格只发送一次。

凭据错误、额度耗尽等 4xx 会暂停发送，修正原因后再“解除发送错误暂停”。只有 HTTP 200 且响应 `status=1` 才计入“接口已接受”；这代表 Pushover 接受并入队，手机实际收到仍需你确认。

损坏的事件、状态或冻结正文会留下 `quarantine` 标记并跳过，其余消息继续处理。原文件和去重键保留，避免把未知状态当成未发送。请先核查原因，再决定如何恢复该记录。

当前可选的项目与精确回合输入查询使用已有 WSL 中的 Python 3；未配置时使用桌面缓存、工作目录及 hook 捕获值。查询脚本已嵌入 EXE，不需要外部 `.py` 文件。Windows 需要可用的 .NET Framework 4.x（本机为 4.8）；不能把“单文件”理解为所有电脑都不需要运行环境。

## 命令行备用操作

在 PowerShell 中先设置 EXE 路径，再执行需要的操作：

```powershell
$exe = Join-Path $env:LOCALAPPDATA 'CodexPushover\CodexPushover.exe'
& $exe --settings
```

| 参数 | 用途 |
| --- | --- |
| `--tray` | 启动托盘；保留暂停通知设置 |
| `--settings` | 打开设置；进程未运行时也会启动后台 |
| `--status` | 输出状态；需要捕获输出时用 `& $exe --status \| Out-String` |
| `--disable` | 暂停通知；后台可继续留在托盘 |
| `--enable` | 解除主动暂停并请求启动后台 |
| `--resume` | 请求常驻程序解除发送错误暂停；程序已退出时先打开它 |
| `--test` | 排队发送一条测试通知 |
| `--suggestions on` / `--suggestions off` | 开启或关闭输入框建议提醒，并保存选择 |
| `--input-reminders on` / `--input-reminders off` | 开启或关闭需要回答时提醒，并保存选择 |
| `--exit` | 主动退出并保留队列 |
| `--uninstall` | 删除本工具的 hooks 和快捷方式，停止通知，保留私有数据 |

卸载后，其他 hooks 和 Codex 设置保留。确认两个进程都停止后，可以删除 EXE；凭据、队列、日志和备份是否删除，由你决定。

本次部署的实际结果：

| --- | --- |
| 1.2.1 窗口与后台 | 已安装；托盘、守护和登录启动项正常，待发及错误暂停均为 0 |
| 自身控件布局与渲染 | 8 种场景通过，默认 920 × 860 下无需滚动；小窗口可滚动到输入控件 |

## 备份与恢复

程序在修改 hooks 前，将原 hooks.json 和存在的 config.toml 保存到私有目录的 backups 子目录。此备份属于本机配置，不能发布到仓库或复制到另一台电脑。

只想保留正式回复通知时，关闭“输入框建议提醒”和“需要回答时提醒”即可。重新打开开关不会重发已经取消的交互提醒。

恢复配置时先退出通知程序，只合并需要恢复的本工具定义，保留其他 hooks 和后来新增的设置；定义变化后在 Codex 中重新审核。保留 credentials.json、events、state 和 prompts，避免丢失待发消息或去重记录。

仓库只保留当前分发文件。旧版本用 Git 标签和提交比较查看；不要直接把旧程序套在未经核对的新队列格式上。
