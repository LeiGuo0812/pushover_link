# 从源码构建 1.2.1

使用 Windows 自带的 .NET Framework 4.x C# 编译器，不需要 Node 或额外的 .NET SDK。

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\src\Build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Run-CoreTests.ps1
```

构建输出为 `src\CodexPushover.exe`。图像资源与元数据查询脚本均嵌入该 EXE；`dist\CodexPushover.exe` 是已验证的发布文件，普通构建不会覆盖它。

源码 ZIP 采用平铺布局，解压后使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1`。完整核心测试入口在仓库的 `tests/Run-CoreTests.ps1`。构建只使用包内的 `Metadata.py`，不会再从某台电脑的安装目录复制旧脚本。

## 文件分工

| 文件 | 用途 |
| --- | --- |
| App.cs | 入口、安装、托盘、本地命令与状态读取 |
| NotificationCore.cs | hook、交互提醒开关、去重、队列、正文和 HTTPS 发送 |
| ProcessHost.cs | 双进程监督、心跳和启动快捷方式 |
| SettingsForm.cs | 中文设置窗口与蓝色控件 |
| UiAssets.cs / IconMaker.cs / icon-master.png | 高清图像和多尺寸图标 |
| Metadata.py | 按本机配置只读查询 WSL 项目和回合输入 |

## 验证边界

39 项核心测试在隔离临时目录使用假凭据和模拟发送，不读取生产凭据，不调用真实 Pushover。绝对超时测试连接本机回环 HTTP 服务，约需 10 秒。`src/RunUiValidation.ps1` 另外检查 8 种窗口尺寸、缩放和滚动场景；发现布局错误会返回失败。

`src\RunUiValidation.ps1` 渲染独立设置窗口并检查布局，不启动发送后台。它不能验证实际拖动、跨显示器切换或手机接收。

## 配置与分发

新电脑的凭据、后端配置与 hook 审核见[配置与原理](配置与原理.md)。不要复制原电脑的凭据、队列或信任记录。

`examples/` 提供不含真实凭据的 JSON 示例。实际 hooks 由 `--install-hooks` 按本机路径生成，用户仍须在 Codex 中审核。

`dist/` 只保留当前版本的 EXE、配套说明包和源码包；旧版通过 Git 标签与提交查看。发布前应核对包内源码、说明和 EXE，排除凭据、事件、队列、日志及信任配置。版本号以 `App.cs` 的 Program.Version 和程序集文件版本为准；app.manifest 中的 1.0.0.0 是稳定的应用身份。
