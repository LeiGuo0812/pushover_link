# Codex 手机通知：单文件 EXE 配置与复用

版本：1.2.1 · 更新：2026-11-02

当前可独立开启输入框建议和提问提醒。两类开关自动保存，配置缺少选项时默认关闭；需分别开启并在 Codex 界面信任所用 hooks。详细操作见[交互提醒](交互提醒.md)，当前验证结果见[使用说明](使用说明.md#验证记录)。旧版本实现可通过 Git 标签和提交比较查看。

这套工具把 Codex 主会话每轮结束时的项目名称、用户输入和回复发送到 Pushover。Windows 托盘负责状态和设置；手机通过 Pushover 接收，电脑不需要与手机建立 Codex Remote 连接。

## 1. 通知怎样送出

```text
UserPromptSubmit → 保存该轮输入，识别自动建议回合
Stop             → 保存正式回复或输入框建议 ─┐
PreToolUse       → 保存问题与选项 ──────────┴→ 持久队列 → EXE 后台 → Pushover → 手机
```

三个 Codex 事件共用 `CodexPushover.exe hook`。事件字段和审核以[官方 Hooks 协议](https://learn.chatgpt.com/docs/hooks)为准。每次调用只做本地处理，返回 `{}`，不阻止回合结束或代替用户回答。正式回复和建议按真实 `session_id + turn_id` 去重；提问额外加入事件类别和 `tool_use_id`，所以同一轮多个问题及最终回复不会互相覆盖。

前两项足以支持正式回复和可按 Tab 采纳的自动输入建议。第三项只匹配 `request_user_input`、`request_user_input_async` 及其 `functions.` 前缀，用于提问时提醒。它不覆盖不经过该本机 hook 的提示；普通文字问句仍在回合结束时随回复推送。

后台在首次发送前固定正文，重试不会重新拼接其他回合的输入。只有 HTTP 200 且响应 `status=1` 才标记“Pushover已接受并入队”。超时后仍可能出现重复，接口接受也不等于手机已经收到。正文限制和接口结果见 [Pushover API](https://pushover.net/api)。

程序采用 Windows 自带的 .NET Framework 4.x，不需要 Node 或额外服务器。本机目前通过已有 WSL Python 3 只读查询项目和精确回合输入；查询脚本嵌入 EXE。换电脑时应检查实际后端，不要直接复制本机的 WSL 路径。

## 2. 在另一台 Windows 电脑安装已有 EXE

1. 准备 Codex 桌面版、手机 Pushover，以及自己的 Application Token 和 User Key。先确认桌面版本支持用户级 Stop、UserPromptSubmit 和 PreToolUse，并核实提问工具是否经过本机 hook；不支持时说明缺失功能，不能用 CLI 的成功代替桌面支持。
2. 只复制 `CodexPushover.exe`。不要复制旧电脑的凭据、队列、信任记录或 `installation.json`。
3. 在 PowerShell 切换到 EXE 所在目录，执行：

```powershell
.\CodexPushover.exe --install
```

安装入口把 EXE 放入当前用户私有目录，创建凭据模板和设置文件，并添加登录启动、桌面和开始菜单快捷方式。之后使用已安装的路径：

```powershell
$exe = Join-Path $env:LOCALAPPDATA 'CodexPushover\CodexPushover.exe'
& $exe --settings
```

在设置中填写本机凭据并保存。目录是 `%LOCALAPPDATA%\CodexPushover`，凭据仅放在其中的 `credentials.json`；不要发到聊天里。

4. 让 Codex 识别这台电脑的实际配置目录和运行后端。安装入口默认使用当前用户的 `.codex`；如果桌面使用其他目录，先正确设置私有 `installation.json` 的 `config_home`，再运行 `--install-hooks`。项目与输入查询需要以下实际值：

| 配置键 | 这台电脑需要填写的内容 |
| --- | --- |
| `config_home` | 当前桌面实际使用的 Codex 配置目录 |
| `metadata_wsl_executable` | 本机 `wsl.exe` 的绝对路径 |
| `metadata_wsl_distro` | 正在运行 Codex 后端的 WSL 发行版名称 |
| `metadata_sqlite_path` | 该后端实际使用的只读 SQLite 数据库路径 |

已有 EXE 直接支持这类 WSL 查询。如果这台电脑采用原生 Windows 后端，先验证桌面项目缓存和精确 hook 输入能否满足要求；必要时适配本机只读元数据查询。不要为了照抄旧配置擅自安装 WSL。

5. 确认配置目录和后端信息后，运行 `& $exe --install-hooks`。在 Codex“设置 → Hooks”刷新，查看并信任 `UserPromptSubmit`、`Stop`、`PreToolUse` 三项。三项均指向同一 EXE 的 `hook` 入口，PreToolUse 的 matcher 只包含提问工具。不同事件分别注册，不能复制其他电脑的信任记录。
6. 在通知设置中开启需要的交互提醒。从托盘发送测试，区分接口接受与手机收到；再做真实桌面回合及一次提问，核对事件、回合标识和手机显示。仅有手机接收反馈、却没有对应本机记录时，应标注待核实，不能宣布整个 hook 路径已通过。

## 3. 使用与恢复

双击托盘打开设置，关闭设置窗口会保留后台。每轮正式回复一条，开启交互提醒后另发对应建议或问题。用户输入默认最多显示 200 字符，每条正文最多 1024 个 Unicode 字符；超长时截断并标注。

“输入框建议提醒”和“需要回答时提醒”独立保存，重启后保留。关闭某类会取消它尚未发送的记录，重新开启不会补发这些记录；已发出的请求无法撤回。窗口默认内容区为 920 × 860（100% 缩放），屏幕空间不足时允许滚动。

窗口、按钮和托盘菜单统一采用蓝色 `#2563EB`，文字使用微软雅黑 UI。1254 × 1254 高清图片和多尺寸 ICO 嵌入 EXE，托盘按实际尺寸选择图标帧。正文随窗口宽度布局，较小窗口可以滚动，操作按钮保持可见。状态查询和设置写入在后台执行；拖动时延后文字刷新，发送和心跳继续运行。本机 175% 缩放下的中文裁字和数值框重复缩放问题已修复。

关闭“手机通知”开关会停止新回合入队并保留旧队列。凭据或额度导致的错误，应先修正原因，再点“恢复发送”或托盘中的“解除发送错误暂停”。“退出程序”会等待当前发送结束，退出后 hooks 不会马上拉起；下次手动打开或登录启动会恢复。主动暂停会跨重启保留。

登录启动项在 `shell:startup` 中，名称为 `Codex 手机通知.lnk`，目标是 EXE，参数 `--tray`。重启后登录 Windows 才会启动，本工具不是系统服务。

一个 EXE 会运行两个常驻进程：托盘进程负责发送，守护进程负责恢复。托盘每 5 秒检查守护，守护每 10 秒检查托盘；超过 120 秒没有心跳或发送进度时，核对进程身份后尝试重启。常驻监督恢复每端每 5 分钟最多启动 6 次，hook 唤醒另有 30 秒节流。两者都失效时，靠下次有效 hook、登录或手动打开恢复。

网络请求最长等待约 10 秒。网络错误和 5xx 按 5 秒、30 秒重试，之后每 15 分钟探测，持续断网时保留记录。4xx 会暂停；损坏记录会单独隔离，避免阻塞健康队列。关机、注销和休眠期间不能推送。

## 4. 查询、关闭与卸载

```powershell
$exe = Join-Path $env:LOCALAPPDATA 'CodexPushover\CodexPushover.exe'
& $exe --status | Out-String
```

按需执行下表中的一个命令：

| 命令 | 效果 |
| --- | --- |
| `& $exe --disable` | 暂停通知，保留后台和旧队列 |
| `& $exe --enable` | 恢复通知并请求启动后台 |
| `& $exe --suggestions on` / `off` | 开启或关闭输入框建议提醒 |
| `& $exe --input-reminders on` / `off` | 开启或关闭需要回答时提醒 |
| `& $exe --exit` | 主动退出，保留待发记录 |
| `& $exe --uninstall` | 删除本工具的 hooks 和快捷方式，保留其他设置及私有数据 |

卸载并确认进程全部停止后，可按需删除 EXE。

不要删除 `events` 或 `state` 来处理发送故障，它们记录待发消息和已接受状态。删去重记录可能导致旧消息重发。检查脱敏 `sender.log`、`quarantine` 和托盘状态，再决定如何处理。

## 5. 配置文件与验证

程序默认把数据放在 %LOCALAPPDATA%\CodexPushover。源码仓库的 examples 目录提供空凭据、通知选项、三项 hooks 和元数据配置示例；压缩包中也包含 examples。示例只用于对照字段，实际路径由本机安装与环境检查确定。

| 文件 | 当前用途 |
| --- | --- |
| credentials.json | PUSHOVER_APP_TOKEN 和 PUSHOVER_USER_KEY；只在本机填写 |
| notification-options.json | 内容格式、显示长度和两个交互提醒开关 |
| installation.json | 实际 Codex 配置目录、安装信息及可选的 WSL 元数据查询路径 |
| 实际 Codex 目录下的 hooks.json | UserPromptSubmit、Stop、PreToolUse 三个事件共用 EXE 入口 |
| events / state / prompts | 待发事件、已接受或已取消状态、精确回合输入及建议分类 |

通知选项中的 notify_composer_suggestions 与 notify_input_requests 都是布尔值，缺省 false。通过设置窗口或对应 CLI 命令修改，会同时处理该类待发记录；直接编辑 JSON 不提供同样的立即取消操作。content_mode 使用 user_input，user_input_max_chars 默认 200、范围 8–400；conversation_title_max_chars 保留供旧格式兼容。

安装模板不会填入别人的路径或凭据。installation 示例中的空元数据字段表示未启用该查询；只有核实本机已有 WSL、Python 和数据库路径后才填写。hooks 示例中的 command 路径也须替换，建议由 --install-hooks 生成实际配置并保留其他 hooks。

当前已通过 39 项核心测试和 8 项布局检查；两类合成发送获 Pushover 接受，安装电脑上三项 hooks 已受信任。用户报告收到真实提问通知，但该次本机 hook 记录尚未关联，因此真实触发链路仍未核实。手机确认、接口结果、合成测试和真实桌面事件应分别记录。

更换电脑或 Codex 更新后，核对实际事件与信任状态。不要用删除 events/state 的方式“重置”发送故障；先检查托盘状态与脱敏日志，避免重复发送。

## 6. 让 Codex 从头构建的完整提示词

把下面整段发送给目标电脑上的 Codex。它描述功能和验证要求，不依赖本机旧源码。

```text
请直接在这台 Windows 电脑，从头构建并配置一个 Codex 桌面版 Pushover 手机通知工具。完成代码、单文件 EXE、实际安装和验证，不要只给建议，也不要要求我提供旧代码。

界面与安装：
- 生成单个 CodexPushover.exe，带托盘和中文设置窗口。设置包括状态、隐藏的 Pushover 凭据输入、输入长度、手机通知总开关、输入框建议提醒、需要回答时提醒、登录自动运行、发送测试、解除错误暂停、退出和卸载。
- 窗口、按钮、开关和托盘菜单统一使用蓝色 #2563EB，配浅蓝灰背景和微软雅黑 UI。用清晰的中文标签区分接口接受、待发和需处理数量；正文自适应宽度，小窗口允许滚动，底部主要按钮保持可见。
- 默认窗口内容区设为920×860（100%缩放），完整显示新增选项；根据系统DPI缩放，并限制在屏幕工作区内。小屏幕允许滚动到所有设置，不能把控件遮在底部按钮后。
- 嵌入至少1254×1254的高清窗口图像，生成16/20/24/32/40/48/64/128/256像素的多帧ICO，小图标保持简洁，按系统实际托盘尺寸选择帧，不把一张低清图放大。所有资源嵌入EXE。
- 窗体和自绘容器启用双缓冲。状态读取、快捷方式检查、设置写入和其他等待操作在后台执行，采用单次采样缓存；UI只更新变化内容。拖动时延后视觉刷新，但发送和心跳继续工作。整个布局完成后统一DPI缩放，防止子容器重复缩放；原生数值输入控件需单独检查。不要仅添加PerMonitorV2声明就承诺跨屏适配。
- 优先使用本机可用的 .NET Framework 4.8/C# 编译工具；先检查环境，不擅自安装运行时、WSL或框架。保留项目外的完整可审阅源码和构建命令。
- 程序和数据安装在当前用户 %LOCALAPPDATA%\CodexPushover，目录仅当前用户访问。EXE 不内置凭据。创建 credentials.json 模板，字段 PUSHOVER_APP_TOKEN 和 PUSHOVER_USER_KEY，由我在本机设置中填写；聊天、日志和进程参数都不要出现真实凭据。
- 登录启动使用当前用户 Startup 文件夹的 Codex 手机通知.lnk，目标 EXE、参数 --tray。创建桌面和开始菜单快捷方式。正常运行只依赖该 EXE；不要新增计划任务、服务、Node、PowerShell、VBS 常驻发送程序或服务器。
- 提供 --install、--install-hooks、--tray、--settings、--status、--disable、--enable、--resume、--test、--exit、--uninstall，以及 --suggestions on/off、--input-reminders on/off 参数。CLI 解除错误暂停通过本地 IPC 交给常驻进程，避免跨进程改状态；UI 上的等待放后台执行。

先查清本机系统、桌面版本、实际配置目录、后端和元数据位置。按当前版本官方协议实现用户级 UserPromptSubmit、Stop、PreToolUse 三项；PreToolUse只匹配提问工具。共用同一个 EXE hook 入口，根据 hook_event_name 分发；Windows 命令须兼容 PowerShell 和 CMD（可显式使用 cmd.exe /d /c call），验证 UTF-8 中文标准输入及带空格路径。保留其他 hooks，修改前备份，避免重复注册。由我在桌面查看并信任新增或变更定义，不代写信任记录。若当前版本或执行路径不支持某项，如实说明缺失功能。

通知：
- 为自动输入框建议提供独立持久开关：识别明确的 app-generated suggested next user message 指令，按精确 session_id 与 turn_id 保存分类标记。开启时只推送 suggestion 正文，关闭时忽略；不发送生成建议的后台上下文，空建议不推送。不能仅凭 suggestion 或建议二字过滤正常回复。
- 为需要回答的请求提供另一个持久开关。先核对当前本机版本的 PreToolUse 支持；仅匹配 request_user_input、request_user_input_async 及实际验证的名称别名，读取问题与选项。使用真实 session_id、turn_id、tool_use_id 去重，与 Stop 分开。新增 hook 由用户审核，返回 {}，不批准、阻止或改写工具调用；明确不覆盖不经过该 hook 的提示。
- 两个新增开关在设置窗口立即保存，重启后保留；缺省关闭以兼容旧配置。用户要求恢复时开启。关闭某类时取消其尚未发送记录，保留正常回复和 accepted 历史，已在发送的请求不能撤回。测试开关持久化、同轮多个问题、下轮继续、并发去重和关闭取消待发。
- UserPromptSubmit 保存本轮用户输入；Stop 保存本轮回复。只处理主会话，用真实 session_id、turn_id 或经真实事件验证的等价标识关联及去重，绝不能只按会话去重。
- 每轮正式回复一条，标题 Codex 本轮已结束，正文依次显示项目名称、用户输入、本轮回复。交互开关开启时可另发建议或问题，标题分别为 Codex 有新的输入建议、Codex 需要你回答。默认输入200字符，可设8–400；每条整体1024个Unicode字符，超长截断标注。不发送完整历史，不宣称验收成功。
- 使用项目侧栏真实分配信息；精确回合输入优先使用明确 session/turn 标识的只读查询，不能猜最新用户消息。识别问答回复包装时只显示 answer。匹配不到时保留精确 hook 捕获或明确显示未捕获。
- 若本机后端在 WSL，可使用已有 Python3 只读查询 SQLite 和 有扫描大小和时间上限的回合记录；把查询源码嵌入 EXE，通过 stdin 执行，不保留外部Python脚本。子进程总等待不超过约6秒、输出32768字节封顶。其他后端据实际结构适配，不照抄旧电脑路径，不把缺少依赖描述成零依赖。

发送与持久化：
- hook 只快速本地写入和唤醒，约3秒内返回有效 {}，不得请求继续运行、阻止结束或等待网络；网络工作由常驻后台完成，不依赖会话结束可能取消的异步 hook。
- 通过 HTTPS POST https://api.pushover.net/1/messages.json 发送 token、user、title、message，priority=0，不启用重复响铃。桌面程序直接读凭据文件，使用正常证书验证，设置覆盖DNS/连接/响应的约10秒绝对等待上限和响应大小限制。
- 持久化 events、state、prompts 和 control。事件采用原子无覆盖发布，prompt/state采用原子更新。单发送者用用户互斥及文件锁保护；重试前固定正文。
- 只有 HTTP200且JSON数字status=1才标记 Pushover已接受并入队。4xx记录并暂停，修正后可显式恢复；网络错误、5xx有限重试，先5秒、30秒，随后每15分钟探测，长期断网保留记录自动补发。请求开始先持久化15分钟冷却，进程中断后减少重复请求；不能承诺严格只发送一次。日志仅记录固定类型、计数、状态和时间，不记录凭据、请求体、对话或原始错误响应。
- 损坏事件/状态/冻结正文保留原文件与去重键，单独隔离并继续健康队列；不能把未知 accepted 状态重置成未发送。

后台恢复与控制：
- 同一EXE以 --tray 和 --guard 两种角色运行两个轻量常驻进程。托盘约5秒检查守护，守护约10秒检查托盘；核对绝对路径、PID、启动时间和角色，超过120秒心跳或发送进度停滞时才安全恢复，防PID复用和重复实例。每端每5分钟最多重启6次。
- 两个进程都失效时用下一次有效hook、登录或手动启动恢复，明确这个边界。正常退出设置持久标记，守护和hook都尊重退出；下次手动打开或登录 --tray 才恢复。主动暂停跨重启保留，暂停期间新回合不补录。关闭设置窗口保留托盘。
- 暂停/退出/迁移不启动新网络请求，给进行中的请求有限时间完成。迁移标记直接由核心检查，避免新入口绕过。
```
